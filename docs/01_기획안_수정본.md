## 기획의도

**"끊어진 계층 사다리, 첫 칸부터 다시 놓는다."**

같은 청년층 안에서도 순자산 상위 20%와 하위 20%의 격차는 **약 40배**에 이릅니다(국회입법조사처, 2026.7). 사회초년생 때의 첫 재무 선택이 이후의 자산 격차를 키웁니다. 청년들이 겪는 문제는 네 가지이고, **서로 다른 사람의 문제**입니다.

1. **무엇부터 해야 할지 모른다**: 20대의 '재무목표'(36.1점)·'재무점검'(33.2점) 점수가 2년 새 급락 (한국은행·금감원 「2024 전국민 금융이해력 조사」)
2. **나에게 맞는 혜택을 못 찾는다**: 청년정책을 이용하지 않은 이유 2위가 "찾는 방법을 몰라서"(39.3%) (2026.9 청년 설문)
3. **가입해도 유지하지 못한다**: 청년도약계좌 중도해지율 8.2% → 15.9% (2023년 말 → 2024년 말)
4. **모을 돈 자체가 없다**: 정책금융상품은 본인 저축을 전제로 해 저축 여력이 부족한 청년일수록 소외됨 (국회입법조사처). 사다리는 이런 사용자에게 저축 계획보다 **적자 원인과 새는 돈 찾기, 지원 정책**을 먼저 안내합니다.

| 구분 | 이미 하는 것 | 그것만으로 부족한 점 |
|---|---|---|
| 토스·뱅크샐러드 | 계좌 통합 조회, 소비 분석 | 분석이 청년 정책이나 저축 실행 계획으로 이어지지 않음 |
| 온통청년·복지로 | 나이·지역 조건으로 정책 검색 | 내 현금흐름으로 납입을 유지할 수 있는지는 판단하지 않음 |
| **사다리** | **진단 → 유형별 계획 → 혜택 매칭 → 유지 코칭** | 계좌 자동 연동 없음 (직접 입력·업로드 방식) |

## 프로젝트 내용

**서비스 개요**: 사회초년생(만 19~34세, 취업 0~3년 차)이 5분 질문 카드로 재무 진단을 받으면, 진단 결과로 나뉜 **유형에 맞는 첫 실행 계획**과 받을 수 있는 청년 혜택을 받고, 매주 한 번 탭으로 점검하며 계획을 유지하는 반응형 웹 서비스(PWA)

**핵심 흐름**: 재무 진단 → 유형 분류 → 유형별 계획 → 혜택 매칭을 1차(①~③)에 끝까지 완성하고 ④~⑥은 2차에 붙입니다. 유형 분류는 진단 답변을 규칙으로 나누는 단계이며, 혜택 매칭은 모든 유형에 제공합니다.

| 유형 | 진단 결과 (규칙) | 첫 대응 | 1차 범위 |
|---|---|---|---|
| A 적자 | 꼭 나가는 돈이 실수령액보다 많음 | 적자 원인, 줄일 지출 안내 | 안내 |
| B 여력 부족 | 저축 가능액이 실수령액의 10% 미만 | 새는 돈 점검, 지원 정책 매칭 | 매칭까지 |
| C 여력 있음 | 저축 가능액이 실수령액의 10% 이상 | 비상금과 목표 저축 계획 | 전체 흐름 |
| D 유지 어려움 | 납입 중인 금액이 저축 가능액보다 큼 | 납입 가능액 점검, 목표 재조정 | 전체 흐름 |

| 기능 | 내용 | AI 기술 |
|---|---|---|
| ① 진단·유형 분류 | 질문 카드로 소득·고정비·부채·거주·재직·목표를 받아 A~D로 분류 | LLM |
| ② 월급 배분 | 비상금·저축·생활비 배분과 목표 시뮬레이션 (계산은 코드, 설명은 AI) | Agent + 계산 도구 |
| ③ 혜택 매칭 | 자격 조건(나이·소득·거주지·재직 기간)은 표로 정리해 코드가 거르고, 신청 방법·상세는 공고문 검색으로 출처·기준일과 함께 제시 | RAG |
| ④ AI 코치 | "이번 달 30만 원 더 써도 될까?"에 필요한 도구만 골라 조회·계산한 뒤 답변 | AI Agent, Memory |
| ⑤ 주간 체크인 | 납입일 알림과 "이번 주 냈나요?" 한 번 탭 체크로 연동 없이 진행률 갱신. 리포트는 앱 화면과 이메일(동의자) | 자동화 |
| ⑥ 영수증·거래내역 | 영수증 사진에서 금액·항목 추출, 거래내역 엑셀은 국민·신한·카카오뱅크 우선 지원 | 멀티모달 |

**기술적 접근**

- **5개 기술을 한 흐름으로**: 영수증 인식(멀티모달) → DB 반영·재계산 → Agent가 계획 변경 안내(RAG는 정책 질문일 때만) → Memory의 목표·선호 반영 → 체크인 알림(자동화). 이 흐름 전체를 통합 시나리오로 테스트
- **Agent와 검증**: 도구 7개(재무 조회, 지출 판단, 적금 시뮬레이션, 정책 검색·상세, 목표 설정, 메모리 저장) 중 필요한 것만 순서대로 호출. 답변 속 금액을 도구 결과와 대조해 근거 없는 금액은 표시하고, 도구 실패나 필수 데이터 누락 시 추측하지 않고 다시 질문
- **배분 공식**: 저축은 가처분소득의 45%(부모님과 거주 시 60%), 비상금 목표는 (고정 지출 + 생활비) 3개월치, 비상금이 차기 전에는 저축액의 30%를 비상금에 먼저 배정. 시뮬레이션은 연 3.5% 단리·이자소득세 15.4% 가정. 규칙 버전과 가정값을 화면에 표시
- **DB와 Memory 분리**: 계산은 DB의 소득·지출·부채·목표·체크인 이력으로만 하고, Memory에는 동의한 코칭 선호와 목표·약속 요약만 저장. 사용자가 "AI가 기억하는 나" 화면에서 보고 지움
- **개인정보**: 업로드 즉시 계좌·카드번호를 찾아 가린 뒤 처리하고 원본 파일은 저장하지 않음. 외부 LLM에는 가린 엑셀 앞 20행(컬럼 판별용)과 영수증 이미지만 보내며, 탈퇴 시 DB·대화 기록·메모리를 즉시 삭제
- **가드레일**: 투자상품 권유를 차단하고, 예적금은 특정 상품을 추천하지 않고 금리·기간·자격 비교 정보만 제공. 화면에 "정보 제공 목적이며 가입 권유가 아닙니다" 표시
- **기술 스택·비용**: FastAPI + HTML/JS(PWA) 단일 서비스, PostgreSQL, BM25 정책 검색(수백 건 규모라 벡터 DB 없이 시작), Claude Opus 5.5(코치)·Haiku 4.5(추출·리포트·영수증), n8n, Render. API 비용은 테스트 10명 × 60회 기준 약 $60, 개발·CI는 키 없는 모의 AI 모드로 비용 0

**일정 (10/1 ~ 11/8)**: 1주 차 핵심 흐름 MVP 배포 → 2주 차 유형 분류·체크인 → 3주 차 영수증·엑셀·테스트셋 → 4주 차 사용자 테스트(10명, 10/24~) → 5주 차 피드백 반영·발표 준비

## 기대효과 및 활용방안

**기대효과**

- **개인**: 재무 상태에 맞는 첫 행동을 알고, 놓치던 청년 혜택을 찾고, 주간 체크인으로 납입을 이어 감
- **사회**: 정보 접근성 차이가 자산 격차로 이어지는 고리를 완화하고, 청년 자산형성 정책이 가입에서 유지까지 이어지도록 도움
- **측정 지표(사용자 테스트 10명)**: 실행 계획을 끝까지 받은 비율, 혜택 매칭이 맞은 비율, AI 답변의 금액·정책 오류율, 주간 체크인 응답률, SUS 사용성 점수. 목표 수치는 테스트셋으로 기준선을 잰 뒤 팀이 합의해 확정

**활용방안 및 발전 가능성**

- **B2G·B2B**: 지자체 청년센터, 대학 취업지원센터, 중소기업 신입사원 복지용 재무코칭 도구로 공급 (저장 항목·삭제 기능을 갖춰 기관 도입에 대응)
- **B2C**: 기본 무료에 심화 리포트·연말정산 시뮬레이션 등 프리미엄 구독 (투자자문·상품 중개는 제외)
- **확장**: 마이데이터 사업자와 제휴해 자동 연동을 붙이고, 신혼부부·청년 자영업자 등으로 대상 확대
