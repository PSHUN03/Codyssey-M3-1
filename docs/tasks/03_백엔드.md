## [BE-01] [FR-13·14] 거래내역 저장과 소비 분석 API
라벨: 백엔드, FR-13, FR-14, Should
마감: 10/29

**목표**: 거래내역을 저장하고 카테고리별 지출과 저축 여력을 돌려주는 API를 만든다. "모을 돈 자체가 없다(P4)" 문제와 B 유형(저축 여력 부족)의 "새는 돈 찾기"에 대응한다. 기획안 수정본에서 엑셀 변환·분류는 데이터 담당(DATA-06)으로 나눠 백엔드 부담을 줄였다.

**완료 기준**
- [ ] 모델: `Transaction(user_id, date, amount, merchant, category, is_fixed, source)` (`app/models.py`)
- [ ] `POST /api/transactions/upload`: 파일 크기 2MB 제한, 확장자 검사, 원본 파일은 저장하지 않음 (NFR-06). 파일 해석은 DATA-06의 변환 함수를 호출한다
- [ ] `GET /api/transactions/summary?month=`: 카테고리별 합계, 고정비 추정, 구독 후보, 저축 여력
- [ ] 탈퇴 시 거래내역도 함께 삭제되는지 확인 (`ondelete="CASCADE"`)
- [ ] 코치 도구 `analyze_spending` 추가 (`app/services/agent/tools.py`) — AI 담당과 함께
- [ ] 테스트: 가짜 거래내역으로 저장·요약 테스트

**참고**: 변환 함수의 입출력 형식은 DATA-06 담당과 먼저 정한다.

## [BE-06] 배분 공식의 근거 출처 확보
라벨: 백엔드, 멘토피드백, Must
마감: 10/28

**목표**: 저축 45%(부모님과 거주 60%), 비상금 3개월치, 비상금 우선 배정 30%, 금리 3.5%·이자소득세 15.4% 가정이 어디서 왔는지 공식 자료로 보여준다. 멘토 피드백: 계산을 코드로 하는 것에 더해 공식의 근거까지 보이면 금융 서비스로서 신뢰도가 크게 올라간다.

**완료 기준**
- [ ] 각 수치의 근거를 금융감독원·금융위원회 금융교육 자료, 국세청 안내 같은 공식 출처에서 찾아 [ADR-0005](../adr/0005-calculation-in-code.md) 표의 '근거' 칸에 출처 URL과 확인 날짜로 적는다
- [ ] 근거를 찾지 못한 수치는 팀과 다시 정하고 규칙 버전을 올린다 (`app/services/finance/budget.py`의 `RULE_VERSION`, 테스트 수정)
- [ ] 플랜 화면에 가정값과 출처 링크를 표시 (프론트엔드와 협의)
