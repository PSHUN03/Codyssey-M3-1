## [DATA-06] [FR-13] 거래내역 엑셀 변환과 분류
라벨: RAG, 데이터, FR-13, 멘토피드백, Should
마감: 11/3

**목표**: 은행마다 다른 거래내역 파일을 하나의 형식으로 바꾸고 카테고리를 분류한다. 멘토 피드백: 국민·신한·토스·카카오뱅크 파일 모양이 모두 다르니 지원 은행을 정하거나 변환 단계를 따로 두고, 계좌번호·카드번호는 올리는 순간 가려야 한다. 기획안 수정본에서 백엔드 부담을 나누려고 데이터 담당이 맡는다.

**완료 기준**
- [ ] 1차 지원: 국민·신한·카카오뱅크 거래내역 파일. 그 외 형식은 컬럼 매핑 단계로 처리
- [ ] 파일을 읽자마자 계좌번호·카드번호를 찾아 가린 뒤 다음 단계로 넘긴다 (`app/security.py`의 `mask_sensitive` 재사용)
- [ ] 컬럼 매핑: 가린 앞 20행만 경량 LLM에 보내 날짜·금액·가맹점 컬럼을 찾는다 (`llm.structured_call`). 모의 모드에서는 컬럼명 규칙으로 찾는다. 전체 거래내역은 외부 LLM에 보내지 않는다
- [ ] 분류: 가맹점명을 규칙(키워드 사전) → 실패 시 LLM 배치 분류 (100건씩, 가맹점명과 금액만 보냄)
- [ ] 변환 함수의 입출력 형식을 BE-01 담당과 정하고 함께 연결
- [ ] 테스트: 은행별 가짜 거래내역 파일로 파싱·마스킹 테스트. 실제 거래내역은 저장소에 올리지 않는다

**참고**: `openpyxl`은 가벼우니 pandas 대신 표준 `csv` + `openpyxl`로 충분하다. 의존성을 추가하면 `requirements.txt`에 기록한다.
