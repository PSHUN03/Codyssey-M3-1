# ADR-0008: 화면 디자인 시스템과 질문 카드형 진단

- 날짜: 2026-10-01
- 상태: 채택 (시각 체계는 아래 2026-11-01 FE-03 추가 결정으로 갱신)

## 배경
MVP 초안 화면을 팀 안에서 다시 보니 "누가 봐도 AI가 만든 것 같다"는 의견이 나왔다. 원인을 짚어 보면 다음과 같았다.

- 모든 구역이 같은 흰 카드라 정보의 무게가 구분되지 않음
- 알약 모양 배지와 이모지가 화면마다 반복됨
- "AI 답변은 틀릴 수 있어요" 같은 면책 문구가 한 화면에 4~5번 나옴
- 모든 문장이 같은 틀의 "~해요"로 끝나고, "정규직(으)로 기록했어요" 같은 기계적인 조사 표기가 보임
- 데스크톱에서도 모바일 폭 한 줄만 쓰고, 금액을 "2450000"처럼 원 단위로 입력받음
- 대화형 진단은 자유 입력을 해석하느라 오답이 잦고, 답을 고치기 어려움

## 결정

**시각 체계**: Wise의 공개 디자인 시스템을 참고해 우리 서비스에 맞게 줄였다.

| 항목 | 값 |
|---|---|
| 바탕 | 세이지 `#e8ebe6`, 카드는 흰색 |
| 강조색 | 라임 `#9fe870` 하나만 (글자는 `#163300`). 두 번째 강조색은 쓰지 않음 |
| 글자 | 잉크 `#0e0f0c`, 본문 `#454745`, 보조 `#868685` |
| 상태 | 긍정 `#2ead4b`, 주의 `#ffd11a`, 부정 `#d03238` (점과 글자색으로만 표시) |
| 서체 | 제목과 큰 숫자는 Paperlogy 900/800, 본문은 Pretendard |
| 모양 | 카드·버튼 반경 24px, 입력칸은 1px 잉크 테두리에 반경 12px |
| 구분 | 테두리와 그림자 대신 면의 색 차이로 구역을 나눔 |

토큰은 `app/static/css/app.css`의 `:root`에 모여 있다. 발표 자료도 같은 Paperlogy 서체를 써서 화면과 덱의 인상을 맞춘다.

**로고**: 위로 갈수록 길어지는 가로대 세 칸(A안). 늘어나는 자산을 뜻하고 맨 위 라임 칸이 다음 목표다. SVG는 `app/templates/_macros.html`, 아이콘 PNG는 `scripts/make_icons.py`로 만든다.

**진단**: 한 화면에 질문 하나를 보여 주는 카드형으로 바꾼다.
- 일하는 형태, 사는 곳처럼 답이 정해진 질문은 버튼으로, 금액은 만 원 단위 숫자 입력으로 받는다.
- 자유 문장은 목표 하나만 받는다. 규칙으로 금액과 기간을 찾고, 못 찾으면 경량 LLM이 정리한 뒤 사용자가 확인하고 고친다.
- 마지막에 전체 답을 보여 주고 항목별로 고칠 수 있게 한다.
- 질문 정의는 `app/services/onboarding/flow.py` 한 곳에 두고 화면은 API로 받아 그린다.

**문구**: 담백한 존댓말로 쓰고, AI 한계 안내는 코치 화면에 한 번, 각 답변에는 작은 "AI 답변" 표시만 둔다. 조사는 `app/services/text.py`의 `josa()`로 붙인다.

## 2026-11-01 FE-03 추가 결정

팀에서 합의한 보라색 시안에 맞춰 기존 시각 체계를 갱신했다. 랜딩·진단·플랜·혜택의 화면 구성과 이후 세부 정렬·전환 효과는 FE-03의 UI·접근성 범위로 관리한다.

- 강조색은 보라색 `#6d4be4`, 바탕은 `#fbfaff`, 카드 면은 흰색을 쓴다. 화면 제목과 본문은 Pretendard 계열을 사용한다.
- 화면 로고는 보라색 사각형 안의 상승 화살표다. 그래프는 고정비·생활비·비상금·목표 저축을 구분하는 색과 텍스트 범례를 함께 쓴다.
- 주요 버튼의 글자는 중앙에 정렬하고 화살표는 오른쪽에 둔다. 플랜의 주요 동작과 정보 수정 링크는 같은 중심선으로 묶으며, 수정 링크도 최소 44px의 터치 높이를 갖는다.
- 혜택 상세 패널의 문서 아이콘은 장식이다. 공유 기능을 의미하지 않으며, 실제 공유 기능을 추가할 때는 별도 기능 이슈로 관리한다.
- 새 화면의 본문은 240ms 동안 8px 올라오며 나타난다. 새 채팅 말풍선은 260ms 동안 10px 올라오며 나타나고, 답변은 초당 약 45글자의 일정한 속도로 표시한다. 한꺼번에 수신한 글자가 많아도 표시를 가속하지 않는다. 저장된 대화는 다시 타이핑하지 않는다.
- 기기의 동작 줄이기 설정에서는 화면·말풍선 효과와 글자 표시 애니메이션을 생략한다. 스크린 리더에는 준비 상태와 완성된 답변을 안내하고, 검증으로 교체된 답변과 오류는 즉시 표시한다.

## 결과
- 랜딩에 로그인 없이 쓰는 월급 계산기를 두어 첫 화면에서 서비스의 쓸모를 바로 보여 줄 수 있다 (`/api/public/quick-plan`).
- 진단 입력 오류가 구조적으로 줄고, 사용자 테스트에서 "몇 번째 질문인지" 진행 상황을 보여 줄 수 있다.
- 대화형 진단에서 LLM이 맡던 항목 추출은 목표 문장 하나로 줄어 비용과 지연이 줄었다.
- Wise는 참고만 했고 로고, 문구, 화면 구성은 사다리에 맞게 새로 만들었다. 상표나 고유 자산은 쓰지 않는다.
