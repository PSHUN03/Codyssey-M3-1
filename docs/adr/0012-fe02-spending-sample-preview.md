# ADR-0012: FE-02 소비 분석을 샘플 화면으로 먼저 구현

상태: 프론트엔드 샘플 구현. 실제 API 계약은 미합의.

## 배경

#15(FR-14)의 보라색 모바일·PC 목업을 먼저 확인했다. BE-01 #19 및 DATA-06 #37과 업로드·요약·분류 수정 계약을 맞춘 뒤 실제 데이터를 연결해야 한다. 현재 단계에서 실제 파일을 읽거나 업로드한 것처럼 표현하지 않는다.

## 결정

- 최신 main에서 분리한 `codex/FE-02-spending`에서만 작업한다. FE-01·FE-04·FE-05 브랜치의 커밋은 가져오지 않는다.
- 로그인·진단을 마친 사용자에게 `/spending`을 제공한다. 기존 `/plan`에 ‘소비 분석 보기’ 링크만 추가하고 계산·목표·진단·시뮬레이션을 유지한다. 소비 분석에서는 플랜 메뉴가 활성화된다.
- 공통 페이지 제목·본문·보라색 토큰을 재사용하고 CSS·JS는 페이지별로 로드한다. 화면 제목의 위치·크기는 다른 페이지와 같다.
- 파일 선택은 `.xlsx`, `.csv`, 2MiB 이하·빈 파일 여부만 검사한다. 파일 내용을 읽지 않으며 서버·LLM에 보내거나 저장하지 않는다. 진행 표시는 **샘플 결과 준비** 과정이며 실제 업로드 진행률이 아니다.
- `app/services/spending_preview.py`의 가상 거래 10건만 렌더링한다. 날짜는 한국 시간의 이번 달이고 총액·고정비·변동비는 JS에서 같은 거래로 계산한다. 사진·실제 거래내역·계좌번호를 사용하지 않는다.
- 차트는 외부 라이브러리 없이 반응형 SVG 가로 막대로 그린다. 강조색은 보라색 하나, 값과 분류는 텍스트로 함께 표시한다. 컨테이너 너비에 맞춰 다시 그린다.
- 스크롤로 차트가 보이면 위 행부터 65ms 간격으로 한 번 나타난다. 전체 페이지는 기존 240ms 공통 진입 효과를 쓰며, 업로드 카드는 360ms 동안 부드럽게 나타난다. 뒤로가기는 `/plan` 링크로 돌아가므로 공통 진입 효과가 다시 적용된다. 동작 줄이기·관찰 API 미지원에서는 차트를 즉시 보여 준다.
- 거래별 선택은 기존 `initProfileSelects`를 재사용한다. 흰색·둥근 모서리·그림자·선택 체크가 있는 메뉴이며 키보드 방향키·Home/End·Enter/Space·Escape·Tab을 지원한다. 원래 select에 실제 값을 유지한다. 행을 다시 만들지 않아 전역 리스너가 분석할 때마다 늘지 않는다.
- 분류 수정은 이 페이지의 메모리에만 반영한다. 차트·상위 거래의 분류가 즉시 갱신되며 금액·고정비 추정 여부는 바뀌지 않는다. 새로고침·페이지 이탈 시 유지되지 않으며 재분석하면 샘플 원본으로 돌아간다.
- 결과 없음·불러오기 실패는 `?example=empty`, `?example=error`로 확인한다. 실제 장애와 API 처리는 다음 단계에서 연결한다. 현재 단계로 FR-14 전체를 완료 처리하지 않는다.

## API 연결 전 합의할 것

1. BE-01: 업로드의 multipart 필드명, 허용 형식·크기, 동기/비동기 응답, 처리·제외 건수, 오류 코드·메시지.
2. BE-01: `GET /api/transactions/summary?month=YYYY-MM`의 필드, 거래 ID·날짜·원 단위 금액·카테고리 코드, 고정비·구독 후보·상위 지출·기간 범위와 페이지 처리.
3. BE-01: 분류 수정 API의 경로·메서드·요청·응답. 이 엔드포인트는 이슈에 아직 정의되지 않아 임의로 구현하지 않는다. 수정 후 요약을 다시 받는 방식, 저장 실패 시 원래 선택 복구도 맞춘다.
4. DATA-06: 표준 거래 레코드, 출금·입금·취소/환불 부호, 카테고리 목록과 미분류 값, 컬럼 매핑 추가 입력 및 부분 실패 전달 방식.
5. 두 담당자와 원본 미보관·마스킹·인증 만료 처리, 은행별 가짜 파일을 이용한 통합 확인 방법을 정한다.

## 결과

사용자와 모바일·PC UI를 먼저 확인할 수 있다. 실데이터 파싱·업로드·저장, 구독 후보/저축 여력의 실제 계산, API 오류 처리는 검증 범위에 포함하지 않는다.
