# ADR-0005: 금액 계산은 코드가, 해석은 LLM이 한다

- 날짜: 2026-09-30
- 상태: 채택

## 배경
LLM은 산술에서 틀리는 일이 있다. 금융 서비스에서 숫자가 틀리면 신뢰가 무너진다.

## 결정
- 월급 배분, 적금 만기액, 정부기여금, 지출 영향은 모두 `app/services/finance/`의 결정론적 코드가 계산한다. 같은 입력이면 항상 같은 결과가 나온다.
- 코치 Agent는 계산이 필요하면 도구를 호출하고, 시스템 프롬프트로 "도구 결과에 없는 금액을 만들지 말라"고 지시한다.
- **출력 검증**: 응답에 나온 금액을 도구 결과와 대조해, 근거 없는 금액이 있으면 메시지를 `flagged`로 표시한다. 플랜 설명은 근거 없는 금액이 있으면 AI 설명을 버리고 템플릿 설명으로 대체한다.

### 배분 규칙 v1 (팀 검토 대상)
| 규칙 | 값 | 근거 |
|---|---|---|
| 저축 비율 (가처분소득 대비) | 부모님과 거주 60%, 그 외 45% | 사회초년생 대상 금융교육 자료의 일반 권장 범위 |
| 비상금 목표 | (필수지출+생활비) × 3개월 | 일반적인 비상금 권장 기준 |
| 비상금이 부족할 때 | 저축액의 30%를 비상금에 먼저 배정 | 목표 저축과 비상금을 병행 |

## 결과
- 단위 테스트로 계산을 검증할 수 있다 (`tests/test_finance.py`).
- 배분 비율은 규칙이라 사용자에 따라 부적절할 수 있다. 사용자 테스트 피드백으로 v2를 만든다.
