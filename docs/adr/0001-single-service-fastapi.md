# ADR-0001: 화면과 API를 FastAPI 단일 서비스로 만든다

- 날짜: 2026-09-30
- 상태: 채택 (기획 초안의 Next.js + Vercel 분리 구성을 대체)

## 배경
기획 초안에서는 Next.js(Vercel) 프론트엔드와 FastAPI(Render) 백엔드를 분리했다. 개발 PC에 Node.js가 없었고, 팀원 5명의 역량은 아직 파악되지 않았으며, 과정에서 공통으로 익힌 언어는 Python이다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| Next.js + FastAPI 분리 | 업계 표준, 풍부한 UI 생태계 | Node.js 설치 필요, 두 서비스 배포·CORS·인증 연동 부담, 팀원 러닝커브 |
| **FastAPI + Jinja2 + 순수 JS** | Python 하나로 개발, 서비스 1개 배포, 쿠키 세션으로 인증 단순 | 복잡한 인터랙션은 직접 구현해야 함 |
| Streamlit | 가장 빠름 | 모바일 UX·커스터마이징 한계, PWA 불가 |

## 결정
FastAPI가 화면(Jinja2 템플릿)과 API를 함께 제공한다. 동적 기능(채팅 스트리밍, 진단 대화)만 순수 JavaScript로 만든다. 과제 미션의 README 예시 스택(FastAPI, HTML/CSS/JS, Render)과도 같다.

## 결과
- 배포 대상이 하나라 무료 플랜 하나로 운영할 수 있다.
- 모든 팀원이 Python 코드를 읽을 수 있어 교차 리뷰가 쉽다.
- 화면이 복잡해지면 특정 화면만 프레임워크로 옮기는 것을 다시 검토한다.
