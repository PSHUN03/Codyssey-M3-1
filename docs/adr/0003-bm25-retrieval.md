# ADR-0003: 정책 검색은 BM25로 시작하고, 자격 판정은 규칙 코드가 한다

- 날짜: 2026-09-30
- 상태: 채택 (기획 초안의 pgvector 벡터 검색을 대체)

## 배경
RAG 대상은 금융 관련 청년 정책 수십 개, 청크 수백 개 규모다. Anthropic은 임베딩 모델을 제공하지 않아 벡터 검색을 하려면 다른 API 키가 추가로 필요하다.

## 선택지
| 선택지 | 장점 | 단점 |
|---|---|---|
| pgvector + 임베딩 API | 의미 검색 | 키·비용·인프라 추가, 이 규모에서는 과함 |
| **메모리 내 BM25 (음절 바이그램)** | 의존성 0, 빠름, 결과를 설명할 수 있음 | 동의어·의미 검색 약함 |
| LLM에게 전체 정책을 매번 넣기 | 구현 단순 | 비용 증가, 근거 추적 어려움 |

## 결정
- 한국어 형태소 분석기 없이 **음절 바이그램 BM25**로 검색한다. 조사·어미 변화에 강하다.
- 질문에 정책 이름이 그대로 들어 있으면 그 정책을 우선한다. 다른 문서가 그 이름을 여러 번 언급해 순위가 뒤집히는 문제를 막기 위해서다.
- **자격 판정은 LLM이 아니라 `eligibility.py` 규칙 코드**가 한다. 나이·소득·주거 같은 조건은 틀리면 안 되므로 결정론적으로 판단하고, 가구소득처럼 알 수 없는 조건은 '확인 필요'로 남긴다.

## 결과
- 골든셋 12문항에서 hit@1 100%. 골든셋을 40문항으로 늘린 뒤 85% 미만이 되면 임베딩 하이브리드 검색을 도입한다 (`search.py`의 `search_policies`에서 점수를 합치는 방식).
