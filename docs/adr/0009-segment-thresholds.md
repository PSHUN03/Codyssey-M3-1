# ADR-0009: 유형 분류(A~D)의 B/C 기준과 D 판정 범위

- 날짜: 2026-10-30
- 상태: 제안 (11/1 팀 회의에서 결정)
- 작성: @PSHUN03 · 검토: @1yuxnp

## 배경

진단 결과로 사용자를 A~D 유형으로 나누는 규칙이 `app/services/finance/segment.py`에 들어가 있다 (규칙 버전 `v1`). 멘토 피드백에 따라 기획안 수정본에 유형 분류를 넣으면서 기준값 두 개는 팀이 확정하기로 남겨 두었다 (PM-08).

| 유형 | 지금 규칙 (v1) | 판정 순서 |
|---|---|---|
| A 적자 | 꼭 나가는 돈 ≥ 실수령액 | 1 |
| D 유지 어려움 | 지금 매달 넣는 돈 > 계획상 저축 가능액 | 2 |
| B 여력 부족 | 저축 가능액 < 실수령액의 10% (`LOW_SAVING_RATE`) | 3 |
| C 여력 있음 | 그 밖의 경우 | 4 |

기획안 수정본의 유형 표는 A를 "꼭 나가는 돈이 실수령액보다 많음"으로 적었지만 코드는 같은 경우도 A로 본다(쓸 수 있는 돈이 0원이면 저축 계획을 세울 수 없기 때문). 결정 후 기획안 표를 코드에 맞춰 "같거나 많음"으로 고친다.

정할 것은 두 가지다.

1. B와 C를 나누는 10%가 적절한가
2. D를 1원만 많이 넣어도 판정할지, 여유 범위를 둘지

## 지금 규칙이 실제로 뜻하는 것

계산 엔진은 쓸 수 있는 돈(실수령액 − 꼭 나가는 돈)의 45%를 저축으로 잡는다. 부모님과 살면 60%다. 그래서 "저축 가능액이 실수령액의 10% 미만"은 결국 꼭 나가는 돈의 비율로 바뀐다.

| 거주 | B가 되는 조건 | 실수령 250만 원일 때 |
|---|---|---|
| 혼자 살기 등 | 꼭 나가는 돈이 실수령액의 약 77.8% 초과 | 꼭 나가는 돈 약 195만 원부터 B |
| 부모님과 거주 | 꼭 나가는 돈이 실수령액의 약 83.3% 초과 | 꼭 나가는 돈 약 209만 원부터 B |

계산 예 (실수령 250만 원, `calc_budget` 결과):

| 꼭 나가는 돈 | 혼자 살기: 저축 가능액(비율) → 유형 | 부모님과 거주: 저축 가능액(비율) → 유형 |
|---|---|---|
| 180만 원 | 31만 원 (12.4%) → C | 42만 원 (16.8%) → C |
| 190만 원 | 27만 원 (10.8%) → C | 36만 원 (14.4%) → C |
| 195만 원 | 24만 원 (9.6%) → B | 33만 원 (13.2%) → C |
| 200만 원 | 22만 원 (8.8%) → B | 30만 원 (12.0%) → C |
| 210만 원 | 18만 원 (7.2%) → B | 24만 원 (9.6%) → B |

D는 계획상 저축 가능액을 만 원 단위로 내림한 값과 비교한다. 데모 인물 '지우'(계획 65만 원)가 66만 원을 넣고 있으면 1.5%만 많아도 D가 된다. 내림 때문에 계획과 거의 같게 넣는 사람도 D로 갈 수 있다.

## 선택지

### 1. B/C 기준

| 선택지 | 장점 | 단점 |
|---|---|---|
| 1-가. 실수령액의 10% 유지 | 기획안·화면 문구·테스트가 이미 이 기준. 바꿀 것이 없음 | 거주 형태에 따라 실제 경계(필수지출 78%와 83%)가 달라 설명이 한 번 더 필요 |
| 1-나. 꼭 나가는 돈 비율 75% 초과면 B | 사용자가 자기 숫자로 바로 확인 가능. 거주 형태와 무관 | 배분 비율(45%·60%)과 따로 놀아, 부모님과 사는 사람은 저축 여력이 실수령액의 14%쯤 되어도 B가 됨. 코드·문구·테스트 수정 필요 |
| 1-다. 저축 가능액 30만 원 미만이면 B | 금액이라 직관적 | 소득 수준을 반영하지 못함. 실수령 150만 원과 400만 원에 같은 기준 |

### 2. D 판정 범위

| 선택지 | 장점 | 단점 |
|---|---|---|
| 2-가. 지금처럼 1원이라도 많으면 D | 단순함. 바꿀 것이 없음 | 만 원 단위 내림 때문에 계획과 거의 같게 넣는 사람도 D |
| 2-나. 계획보다 10% 넘게 많을 때 D | 내림·입력 오차를 흡수. 비율이라 소득과 상관없이 같은 기준 | 계획이 작을 때(예: 10만 원) 1만 원 차이만 허용 |
| 2-다. 계획보다 5만 원 넘게 많을 때 D | 금액이라 화면 문구로 설명하기 쉬움 | 계획이 클 때는 너무 엄격하고 작을 때는 너무 느슨함 |

## 제안

- **B/C는 1-가(10% 유지)**. 경계가 거주 형태마다 달라지는 것은 배분 비율에서 오는 자연스러운 결과이고, 화면의 B 판정 문구가 이미 "저축 가능액이 실수령액의 몇 %"로 설명한다. 사용자 테스트에서 B 판정에 대한 이의가 나오면 그때 다시 본다.
- **D는 2-나(10% 초과)**. `saving_monthly > total_saving * 1.1`일 때 D. 내림 오차를 흡수하면서 "계획보다 꽤 많이 넣고 있다"는 D의 뜻에 맞는다. 규칙 버전을 `v2`로 올리고 경계값 테스트를 추가한다.

## 결정

(11/1 회의 후 작성) 고른 선택지와 이유, 반대 의견이 있었다면 그 내용.

## 결과

- 기준이 바뀌면 `segment.py`의 상수·문구, `tests/test_segment.py`의 경계값 테스트, 기획안 수정본의 유형 표, 요구사항정의서 FR-23을 함께 고친다.
- 사용자 테스트(11/2~11/4)에서 유형 판정이 자기 상황과 맞는지 묻고(설문), 맞지 않는다는 응답이 30%를 넘으면 기준을 다시 검토한다.
