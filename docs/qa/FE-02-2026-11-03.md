# FE-02 소비 분석 샘플 검증

## 범위

`codex/FE-02-spending`의 `/spending` 및 기존 `/plan` 진입을 로컬 모의 AI·별도 SQLite로 확인했다. 가상 예시 계정과 가짜 거래만 사용했다. 이 기록은 실제 파일 업로드·파싱·API 저장을 검증했다는 의미가 아니다.

## 자동 확인

- Ruff 및 JavaScript 구문 검사 통과.
- `pytest -q` 107개 통과. 신규 Python 검사 6개와 Node 파일·합계·분류 회귀 검사 8개를 포함한다.
- 실제 앱 Chromium 브라우저에서 320×740, **360×800**, 390×844, 736×414, 1024×900, **1440×1000**을 확인한다. 좁은 화면은 터치 환경을 에뮬레이션한다.
- 일반/동작 줄이기의 진입·스크롤 차트·플랜 복귀와 JS 미사용 확인 21개 통과.
- 실제 앱의 파일·분류 메뉴·합계·레이아웃·재시도·기존 계산 확인 204개 통과, 실패 0.
- 기존 검색 평가 12문항 및 가드레일 평가 10문항도 통과했다.

## 재현

1. `/demo` 예시 계정에서 홈·플랜·소비 분석의 제목 위치, 크기, 기준선을 비교한다.
2. 플랜 ‘소비 분석 보기’로 이동한다. 상·하단 플랜 메뉴는 활성 상태이며 공통 진입 효과가 적용된다.
3. 기본 합계 891,800원, 고정비 627,800원, 변동비 264,000원과 카테고리 7개·상위 거래를 확인한다.
4. 차트를 스크롤로 보이게 하면 위 행부터 65ms 간격으로 420ms 동안 한 번 나타난다. 동작 줄이기에서는 바로 보인다.
5. 동네식당의 식비→쇼핑 선택으로 쇼핑 148,000원·식비 100,500원으로 바뀌고 총액은 유지되는지 확인한다. 10건을 펼쳐 월세를 기타로 바꾸면 차트와 상위 지출의 분류도 바뀐다.
6. 흰색 둥근 메뉴·선택 체크, 화면 경계 안 표시, 마우스/터치·방향키·Home/End·Enter·Escape·Tab·바깥 클릭을 확인한다. 선택 후 포커스는 원래 버튼에 남는다.
7. PDF·2MB 초과·빈 파일은 안내한다. 긴 CSV 파일명도 줄 바꿈한다. 실제 파일 읽기나 서버 변경 요청이 발생하지 않는다.
8. ‘샘플 분석하기’ 진행 중 중복 클릭을 막고 결과에서 기본 샘플로 복구한다. 선택한 파일과 무관한 예시 결과임을 표시한다.
9. `?example=empty`·`?example=error`와 재시도를 확인한다.
10. ‘뒤로가기’는 `/plan`으로 돌아가며 공통 효과가 적용된다. 원래 적금 계산(월 30만 원, 24개월)을 다시 실행한다.
11. FE-05의 기존 ‘뒤로가기’도 별도 실행본에서 `/plan` 복귀 시 공통 240ms 효과가 적용됨을 확인했다. FE-05 코드와 브랜치는 변경하지 않았다.
