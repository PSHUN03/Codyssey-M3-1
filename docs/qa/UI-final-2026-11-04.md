# 최종 UI 점검: 입력 오류 중복 안내 수정

## 변경

브랜치 `codex/ui-final-polish`는 2026-11-04 확인한 main `4c15260`에서 시작했다. 마지막 점검까지 UI 수정 사항을 관리하는 Draft PR이며 현재 변경 범위는 공통 입력 검증의 중복 안내다. 기존 FE 브랜치를 병합하거나 수정하지 않았다.

로그인에서 이메일·비밀번호를 비우고 제출하면 각 입력칸 아래에 오류가 나오고 버튼 아래에도 마지막 비밀번호 오류가 반복됐다. 입력칸별 안내를 표시했다면 폼 전체에 같은 문구를 다시 쓰지 않도록 바꿨다. `.field`가 없는 필수 동의 항목은 폼 안내를 유지한다. HTML·CSS·인증·저장 API는 변경하지 않았다.

## 확인 결과

- 수정 전 main의 JS로 모바일에서 입력칸 오류 2개와 폼 하단 비밀번호 오류 1개를 재현했다.
- 수정 후 실제 앱 Chromium **360×800·1440×1000**, 동작 줄이기 설정에서 **42개 검사 통과, 실패 0**.
- 로그인·회원가입의 빈칸, 이메일 형식, 비밀번호 길이, 반복 제출 시 중복·누적 없음과 첫 오류 포커스를 확인했다.
- 입력 수정 시 오류 텍스트·`aria-invalid`가 해제되고 닉네임·비밀번호의 원래 도움말 연결은 유지된다.
- 서버가 반환하는 로그인 실패 안내, 정상 제출의 처리 중 상태·중복 제출 방지, 필수 동의의 전체 안내 및 회원가입→동의→진단 이동을 확인했다.
- 내 정보의 빈 나이 입력은 입력칸 아래에 안내하고 기존 폼 도움말을 덮어쓰지 않는다.
- Ruff, JavaScript 구문, `git diff --check`, **pytest 101개**, 기존 검색 평가 12문항·가드레일 평가 10문항 통과.

가상 계정은 별도 로컬 SQLite에만 만들었다. 운영 배포·실제 iOS Safari·Android Chrome 확인은 이번 검증 범위에 포함하지 않는다.

## 브라우저 검사 재현

별도 테스트 DB·`LLM_PROVIDER=mock`으로 로컬 서버를 실행하고 Playwright가 준비된 개발 환경에서 아래 스크립트를 실행한다. 앱 런타임 의존성은 추가하지 않았다.

```text
node tests/browser/validation-feedback.cjs
```

기본 주소는 `http://127.0.0.1:8788`이며 `UI_QA_BASE_URL`로 로컬 주소를 바꿀 수 있다. 스크립트는 localhost·127.0.0.1만 허용하며 가상 테스트 계정을 만든다. Chromium이 준비돼 있어야 한다. `UI_QA_OUTPUT`은 캡처 경로, `UI_QA_RESULT`는 검사 결과 JSON의 선택적 저장 경로다. 이 수동 브라우저 검사는 기본 CI의 pytest와 별도로 실행했다.
