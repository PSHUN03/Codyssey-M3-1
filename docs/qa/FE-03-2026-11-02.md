## 상태 안내

- 공통 레이아웃에 페이지 이동·연결 상태 안내를 추가했다. 로그인·가입·동의·예시 계정·로그아웃의 일반 제출은 진행 상태와 중복 제출 방지를 제공하며, 뒤로 가기 복귀 시 버튼을 복구한다.
- 필수 입력의 빈 값과 형식 오류는 항목 옆 문구, `aria-invalid`, 연결된 설명과 폼 상태로 안내한다. 오류 문구가 입력 이름에 섞이지 않도록 이름을 명시한다.
- 내 정보는 저장 중·완료·오류를 해당 폼에 유지한다. 기억 삭제에도 진행·완료·실패와 재시도 안내를 둔다.
- 플랜 시뮬레이터는 초기 입력 안내, 빈 값·기간 범위 오류, 계산 중·완료·서버 오류 상태를 표시한다. 숨긴 기간 칸은 화면 배치에서 제외한다.
- 코치는 준비 상태, 스트림 완료 후 busy 해제, 빈 질문·연결 오류 안내와 재입력 동작을 유지한다. 정적 안내 페이지에는 실제로 존재하지 않는 로딩·빈 결과를 만들지 않는다.

## 화면

### 최종 사용자 피드백 — 선택·빈 입력·로그아웃

- 메뉴 항목을 마우스로 누르면 클릭 전에 바깥 `main`으로 포커스가 옮겨 메뉴가 닫히는 현상을 실제 브라우저에서 재현했다. 항목의 마우스 누름에서 기본 포커스 이동을 막고, 필드와 함께 움직이는 메뉴를 화면 스크롤만으로 닫지 않도록 보완했다. 지역·일하는 형태·회사 규모·사는 곳 4개 모두 변경·저장 후 새로고침에도 값과 표시가 유지됨을 확인했다.
- 랜딩 계산기는 보이는 월급·월세·통신비/교통비를 모두 입력해야 적용된다. 빈칸과 월급 0은 경고·첫 오류 입력 포커스·이전 결과 숨김으로 처리한다. 지출은 명시한 0을 허용하고, 부모님과 살 때 숨긴 월세는 검증에서 제외한다. 누락값으로 요청하지 않음과 값을 고친 후 계산 복구를 검사했다.
- 플랜은 두 상품 모두 금액 누락 시 ‘매달 넣을 돈을 입력해 주세요.’, 일반 적금의 기간 누락 시 ‘기간을 입력해 주세요.’를 표시한다. 기존 범위 오류와 구분하며, 청년미래적금은 고정 기간이므로 숨긴 기간 입력을 요구하지 않는다. 두 상품의 정상 계산 복구도 확인했다.
- 공통 유효성 오류의 기본 브라우저 팝업을 취소하고 빨간 인라인 안내와 포커스 이동을 유지했다. 로그인 빈 제출에서 요청이 진행되지 않고 이메일 포커스·항목별 문구가 표시되는 것을 확인했다.
- 로그아웃 진행 안내는 버튼보다 앞의 전용 상태 영역에 표시한다. 버튼의 100% 높이를 없애 진행 문구가 탈퇴 버튼과 겹치지 않도록 했다. 별도 DB·모의 AI의 localhost 예시 서버에서 실제 폼 제출 후 **204 무전환 응답으로 로딩 화면을 유지하는 테스트 조건**을 사용했다. PC·360px 모두 문구와 로그아웃 버튼 사이 8px, 두 버튼 사이 12px, 가로 넘침 없음이었다. 테스트 서버는 종료했다.
- PC·360px에서 두 카드 제목 배경과 카드 좌우 끝 차이는 0px이었다. 제목의 `#5b536d` / `#f2eefb` 대비는 **6.34:1**, 입력·선택 버튼은 모두 높이 56px이었다.
- 전체 pytest **101개** 통과. Node 회귀는 총 **13개**(선택 7개·랜딩/플랜 계산 6개) 통과했다. Ruff·JavaScript 구문·패치 검사도 통과했다.
- 이번 변경은 #16의 UI 일관성, 오류 안내, 포커스·접근성 범위에 적합하다. 계산 엔진·정책 판정은 변경하지 않았다. 최종 휴대폰·스크린 리더 재확인은 별도이며, **Draft 상태 변경·리뷰 전환·머지는 수행하지 않는다.**

- 수정 후 `pytest -q` **100 passed**, Ruff와 `git diff --check` 통과. 이번 변경은 이슈 #16의 ‘명도 대비·키보드 포커스 표시’와 UI 일관성 범위에 해당한다.
