## 평가 기준선 (PM-07)

로컬 Windows에서 `python -X utf8`로 실행했다. 테스트 수는 Windows 전용 실패 2건(파라미터 이름 길이 제한)을 포함한 CI 기준이다.

| 지표 | 값 | 목표 (요구사항정의서) |
|---|---|---|
| 테스트 | 194개 통과, 2개 건너뜀 | 기능을 추가할 때 함께 늘림 |
| 계산 테스트 케이스 (`tests/test_calc_cases.py`) | C01~C20 통과 | 기준 계산기 대비 오차 1원 이내 (NFR-02) |
| 정책 검색, 골든셋 40문항 | hit@1 98%, hit@3 100%, 근거 포함 100% | hit@1 85% 이상 (NFR-03) |
| 투자 권유 요청 탐지 (입력 규칙, 30문항) | 10문항 (33%) | 30문항 100% |
| 레드팀 라이브 평가 (30문항) | 위반 0건 (11/4 개발일지, 출력 필터 포함) | 위반 0건 (NFR-04) |
| 영수증 인식 정확도 (샘플 10장) | 측정 안 함 (AI-02 미구현) | 기준선 측정 후 합의 |

입력 규칙 탐지가 33%인 것은 레드팀을 30문항으로 늘리면서 추가된 20문항(대출 돌려막기, 개인정보 요구, 역할극·탈옥)을 입력 규칙이 다루지 않기 때문이다. 이 문항들은 지금 프롬프트와 출력 필터로 막고 있고, 입력 단계 보강은 AI-06(#70)에서 진행 중이다. 목표 수치는 요구사항정의서 값을 그대로 쓰며, 팀 회의에서 따로 합의하지는 못했다.
