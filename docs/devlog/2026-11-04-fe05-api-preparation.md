# FE-05: AI-02 응답 연결 준비

관련: [#18 담당자 답변과 JSON 예시](https://github.com/PSHUN03/Codyssey-M3-1/issues/18#issuecomment-6606433355), AI-02 #26. 브랜치: `feature/FE-05-receipt-upload`, 기존 Draft PR #53.

## 반영

`app/static/js/receipt-contract.js`에 `fromScanResponse`를 분리했다. 공유된 `date`·`merchant_name`·`total_amount`를 기존 화면의 날짜·가맹점·금액으로 변환한다. 샘플 결과도 같은 외부 필드 형식을 거쳐 변환하므로 기본 화면에서 이 경계를 사용한다.

- `total_amount=null`은 직접 입력할 빈칸으로 유지한다. 품목 합계로 금액을 추측하지 않는다.
- 문자열·소수·음수·안전한 정수 범위 밖 금액도 임의로 원 단위 숫자로 바꾸지 않는다. 기존 폼에서 확인하도록 비워 둔다.
- 통화가 제공되면 KRW인지 확인한다. 잘못된 날짜는 기존 폼 변환/검증에서 비워 확인받는다.
- 화면에 필요한 세 필드만 복사하며 품목·가려진 카드번호는 폼·샘플 기록에 넣지 않는다.
- 사용자가 수정한 값은 기존 확인 폼에서 다시 검증한다. 최초 인식 값을 사용자 확인 값 위에 덮어쓰지 않는다.

사진 전송 필드명과 확인 결과 저장 API는 아직 확정되지 않아 전송·저장 함수를 만들지 않았다. 사진 로컬 미리보기·샘플 저장·보라색 UI·체크 효과·진입/복귀 효과를 유지한다. 실제 HTTP 요청이나 DB 저장은 하지 않는다.

## 실제 연결 시 이어서 할 일

AI-02 구현 PR/테스트 환경과 multipart 파일 필드명을 받은 뒤 `/api/receipts/scan` 요청을 연결한다. 응답을 `fromScanResponse`→기존 폼 값 변환에 넣고, 네트워크 실패·인증 만료를 실제 흐름에서 처리한다. 확인한 결과는 별도로 합의한 저장 API 성공 후에만 실제 저장 완료로 알린다.

## 검증

- Node 응답 계약·기존 검증 15개 통과. 외부 필드 변환, 금액 null/형식 오류, 품목으로 추측하지 않기, 비원화 거부, 사용자 수정 값을 확인했다.
- pytest 107개, Ruff·JS 구문·diff 검사 통과.
- 실제 앱 360px·1440px에서 기존 샘플·금액 누락·직접 수정·샘플 완료·보라색과 화면 폭 확인 16개 통과. 샘플 동작 중 서버 변경 요청 및 JS 오류 0.

Codex로 응답 변환과 회귀 검사를 작성했다. 인식·실제 저장을 수행했다고 표시하지 않으며, 미확정된 요청 필드와 저장 계약을 임의로 정하지 않았는지 검토했다.
