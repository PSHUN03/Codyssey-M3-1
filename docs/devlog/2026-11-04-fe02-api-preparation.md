# FE-02: DATA-06 미리보기 연결 준비

관련: [#15 담당자 답변](https://github.com/PSHUN03/Codyssey-M3-1/issues/15#issuecomment-6606918026), DATA-06 PR #56, BE-01 #19. 브랜치: `codex/FE-02-spending`, 기존 Draft PR #54.

## 반영

`app/static/js/spending-contract.js`에 확인된 미리보기 계약을 분리했다.

- `POST /api/transactions/preview`: multipart `file`, 선택적 `mapping` JSON 문자열과 `header_row`. CSV/XLSX·2MiB를 검증하고 Content-Type은 직접 지정하지 않아 브라우저가 multipart boundary를 정한다.
- 열 번호·제목 행은 0부터, 부분 오류의 `row`는 1부터 시작한다. 열 선택 필요·부분 오류·빈 결과·정상 결과를 구분하고 부분 오류는 사용자 확인이 필요함을 남긴다.
- 출금 음수는 지출 표시용 양수로 변환하며 입금은 소비 합계에서 제외한다. 실제 거래 ID가 없는 미리보기에는 표시용 `previewIndex`만 쓰며 저장된 거래 ID로 취급하지 않는다.
- 서버 분류 10개는 별도 계약 목록으로 관리한다. 현재 UI의 카페·구독 등 샘플 분류와 섞어서 실제 API에 보내지 않는다.
- 고정비·변동비는 미리보기 응답에 없으므로 `null`로 남긴다. 값을 추정하거나 0원으로 확정하지 않는다.
- 필수 응답 필드·날짜·정수 금액·건수·합계 범위를 검사한다. 카드번호 등 불필요한 필드는 응답 객체로 복사하지 않는다.
- `createPreviewClient(transport)`는 전송 함수를 명시해야 만들 수 있다. 인증·동의·진단·422·서버 오류를 성공 결과로 바꾸지 않는다. 기본 샘플 화면에서는 이 클라이언트를 생성하거나 호출하지 않는다.

기존 샘플 데이터 접근은 `createSampleSource`로 분리했다. 샘플 카드·카테고리 메뉴·합계·차트·스크롤 효과·CSS와 파일 미전송 동작은 유지한다.

## 실제 연결 시 이어서 할 일

1. PR #56이 포함된 테스트 환경을 확인한다. main이나 현재 FE-02 브랜치에 다른 담당자의 코드를 임의 병합하지 않았다.
2. 실제 미리보기 모드에서 전송 함수를 명시적으로 주입하고 응답을 동적 거래 행·서버 분류 목록에 연결한다. 열 선택 UI와 부분 오류 확인 UI는 활성화 단계에서 기존 보라색 구성으로 붙인다. 현재 준비 코드는 해당 응답을 구분할 수 있게 한 단계다.
3. BE-01의 저장·월별 요약·분류 수정 계약과 거래 ID를 받은 뒤 저장 기능을 연결한다. 파일 재전송/JSON 저장 중 어느 흐름을 쓸지 아직 가정하지 않는다.
4. 고정비·구독·환불 처리 등 최종 집계는 BE-01 요약 계약에 맞춘다. 실제 기록을 샘플 수치와 섞지 않는다.

## 검증

- Node 계약·샘플 회귀 19개 통과. 출금 -5,000원·입금 2,450,000원 예시, 열 선택·부분 오류·빈 결과, FormData 필드, 경계값과 모의 전송 오류를 확인했다.
- pytest 107개, Ruff·JS 구문·diff 검사 통과.
- 실제 앱 360px·1440px에서 기존 메뉴·차트 재계산·샘플 분석·보라색과 화면 폭 확인 16개 통과. 샘플 동작 중 서버 변경 요청 및 JS 오류 0.

Codex로 미리보기 요청·응답 분리와 검사를 작성했다. 실제 API 활성화·저장 완료와 구분하고 UI 기본 동작이 보존되는지 검토했다.
