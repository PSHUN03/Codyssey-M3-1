## 문제와 해결

### 1. 조사가 붙은 계좌번호를 가리지 못함
- 문제: "110-123-456789**로** 들어와요"에서 계좌번호가 마스킹되지 않았다.
- 원인: 정규식 `\b`(단어 경계)는 한글도 단어 문자로 보므로, 숫자 뒤에 조사가 붙으면 경계가 생기지 않는다.
- 해결: `\b` 대신 `(?<!\d)`, `(?!\d)`(앞뒤가 숫자가 아님)로 바꾸고 회귀 테스트를 추가했다.
- 배운 점: 한국어 서비스의 정규식은 조사 결합을 항상 테스트해야 한다.

### 2. 정책 이름으로 물어봐도 다른 정책이 1위로 검색됨
- 문제: "청년도약계좌 지금 가입할 수 있어?" → 청년미래적금이 1위.
- 원인: 미래적금 문서가 "청년도약계좌와 중복 가입 불가", "도약계좌에서 갈아타기"처럼 도약계좌를 여러 번 언급해 BM25 점수가 더 높았다.
- 해결: 질문에 정책 이름이 그대로 들어 있으면 그 정책을 우선하는 보정을 넣었다 (ADR-0003).

### 3. 저소득 요건 정책이 고소득 사용자에게도 '확인 필요'로 노출됨
- 문제: 연봉 3,400만 원인 1인 가구에게 청년내일저축계좌(중위소득 50% 이하)가 상위에 추천됐다.
- 해결: 독립 거주자에 한해 2026년 1인 가구 기준 중위소득(월 256만 4,238원)으로 소득 상한을 추정하는 규칙을 추가했다. 부모와 함께 살면 가구소득을 알 수 없으므로 '확인 필요'로 둔다.

### 4. 배포 후에도 예전 CSS가 보이는 문제 (서비스 워커 캐시)
- 문제: CSS를 고쳤는데 브라우저에서는 계속 이전 스타일이 보였다.
- 원인: PWA 서비스 워커가 정적 파일을 '캐시 우선'으로 제공해, 한 번 저장된 CSS·JS가 영원히 쓰였다. 실제 배포 후 사용자에게 수정 사항이 전달되지 않는 버그다.
- 해결: CSS·JS 주소에 서버 시작 시각 기반 버전(`?v=`)을 붙이고, 서비스 워커를 '캐시로 즉시 응답 + 백그라운드 갱신'(stale-while-revalidate) 방식으로 바꿨다. 캐시 이름도 v2로 올려 이전 캐시를 지운다.
- 배운 점: PWA는 캐시 전략과 버전 관리를 함께 설계해야 한다.

### 5. 자격 확인 목록의 라벨 줄바꿈
- 문제: 모바일에서 "소득", "추가 확인" 라벨이 체크 표시 아래로 줄바꿈됐다.
- 해결: 목록의 왼쪽 라벨은 줄어들지 않게(`flex: none`), 오른쪽 설명만 줄바꿈되게 CSS를 고쳤다.

### 6. Windows 경로 길이 제한
- 문제: 긴 경로의 가상환경에 `anthropic` 패키지를 설치하다 실패했다 (260자 제한).
- 해결: 가상환경을 짧은 경로에 만들고 README에 주의사항을 적었다.
