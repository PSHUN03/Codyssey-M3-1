# 배포 가이드 (Render 무료 플랜)

> 관련 결정: [ADR-0004](adr/0004-hosting-and-database.md)

## 1. 처음 배포하기 (Blueprint, 약 10분)

1. GitHub 저장소에 코드를 올린다 (`main` 브랜치).
2. [Render 대시보드](https://dashboard.render.com) → **New → Blueprint** → 저장소 선택 → **Apply**
   - `render.yaml`대로 웹 서비스 `sadari`가 만들어진다 (무료 플랜, 싱가포르 리전).
   - `SECRET_KEY`와 `INTERNAL_API_KEY`는 Render가 임의 값을 자동 생성한다.
3. 배포가 끝나면 `https://<서비스이름>.onrender.com/health`가 `{"status":"ok"}`를 돌려주는지 확인한다.
4. 이 상태에서는 **모의 AI 모드**로 동작한다 (코치 화면 안내 문구에 모의 모드라고 표시).

## 2. 실제 AI 연결하기

1. [Anthropic Console](https://console.anthropic.com)에서 API 키를 발급한다. 결제 수단과 월 사용 한도(예: $30)를 설정한다.
2. Render 서비스 → **Environment** → `ANTHROPIC_API_KEY`에 키를 붙여넣고 저장한다. 서비스가 자동으로 재시작된다.
3. `/health`의 `llm_provider`가 `anthropic`인지 확인한다.

> API 키는 팀 채팅방·코드·문서에 붙여넣지 않는다. Render 대시보드와 각자의 `.env`에만 둔다.

## 3. 데이터베이스 연결하기 (사용자 테스트 전, 11/1)

무료 PostgreSQL은 **생성 30일 후 만료**된다. 11/1에 만들면 12/1에 만료되어 발표(11/12~13)까지 충분하다. 만든 날짜와 만료일을 README에 적는다.

1. Render → **New → PostgreSQL** → 무료 플랜, 웹 서비스와 같은 리전(싱가포르)
2. 생성된 DB의 **Internal Database URL**을 복사한다.
3. 웹 서비스 → Environment → `DATABASE_URL`에 붙여넣는다. 앱이 `postgres://` 형식을 자동으로 변환하고, 시작 시 테이블을 만든다.
4. 가입 → 재시작(Manual Deploy) → 다시 로그인되는지 확인해 데이터가 유지되는지 검증한다.

**대안 (만료 없음)**: Supabase 무료 프로젝트를 만들고, Connection string(URI)을 `DATABASE_URL`에 넣는다.

## 4. 운영 체크리스트

| 항목 | 방법 |
|---|---|
| 콜드 스타트 | 무료 플랜은 15분 동안 요청이 없으면 잠든다. 시연 10분 전에 접속해 깨우고, 백업 시연 영상을 준비한다. |
| 헬스 체크 | UptimeRobot 같은 무료 모니터로 `/health`를 확인한다 (잠들지 않게 하려는 과도한 호출은 금지). |
| 로그 | Render → Logs. `근거 없는 금액 감지` 경고는 AI 품질 검토 대상이다. |
| 비용 | Anthropic Console의 사용량 대시보드를 매주 확인하고, 주간 회의에서 공유한다. |
| 롤백 | Render → Deploys에서 이전 배포를 선택해 **Rollback**한다. |
| 데이터 삭제 | 프로젝트가 끝나면(12/31) DB와 서비스를 삭제한다 (개인정보처리방침 약속). |

## 5. n8n 연결 (자동화 담당)

1. n8n에서 HTTP Request 노드로 `GET https://<서비스>/internal/ping`에 헤더 `X-Internal-Key: <INTERNAL_API_KEY>`를 보내 연결을 확인한다.
2. `INTERNAL_API_KEY` 값은 Render 대시보드에서만 복사한다.
3. 워크플로우 설계는 [n8n/README.md](../n8n/README.md)를 참고한다.
