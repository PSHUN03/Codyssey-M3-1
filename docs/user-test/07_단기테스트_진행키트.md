## 5. 진행자 스크립트 (대면, 화면 공유)

관찰할 수 있는 방식이 가장 좋습니다. 진행자는 도와주지 않고 기록만 합니다.

1. **시작 (2분)**: "서비스를 평가하는 거지 참여자를 평가하는 게 아니에요. 생각나는 걸 소리 내어 말해 주시면 도움이 돼요. 언제든 그만둘 수 있어요." 동의 여부를 확인하고, 실제 정보와 예시 계정 중 하나를 고르게 합니다.
2. **과제 (10~12분)**: 4장의 ①~④를 하나씩 말로 줍니다. 참여자가 물어봐도 "어떻게 하실 것 같으세요?"로 되돌립니다.
3. **설문 (5분)**: 구글 폼 링크를 주고 그 자리에서 작성하게 합니다.
4. **짧은 질문 (2~3분, 선택)**: "가장 헷갈렸던 화면은 어디였어요?", "친구에게 이 서비스를 한 문장으로 설명하면요?"

### 관찰 기록 (관리 CSV에 바로 입력)

| 열 | 적는 법 |
|---|---|
| T1 진단 완료(분) | 가입 버튼부터 진단 결과 화면까지 걸린 분. 못 끝내면 `X`, 예시 계정이면 비움 |
| T2 배분 설명 | 배분 이유를 자기 말로 설명하면 `O`, 못 하면 `X` |
| T3 혜택 찾기 | 신청 방법이나 공식 출처까지 찾으면 `O`, 못 찾으면 `X` |
| T4 코치 만족도(1~5) | 질문 후 참여자에게 직접 묻기 |
| T5 약속 저장 | 설정의 '기억'에 약속이 남아 있으면 `O`, 없으면 `X` |
| 메모 | 막힌 화면, 헷갈린 용어, 인상적인 말 (그대로 받아 적기) |

T6(1주일 재방문)은 이번에는 측정하지 않으므로 비워 둡니다.

## 6. 구글 폼 만들기

폼은 [08_구글폼_생성.gs](08_구글폼_생성.gs)를 script.google.com에서 실행해 만듭니다. 문항과 각 문항이 확인하려는 것은 [03 설문지](03_설문지.md)에 있습니다.

- 구성: 동의(P1), 응답자 정보(A1~A6), 사용한 기능(U1~U3), 사용 편의성 SUS(B1~B10), 기능별 평가(C1~C9), 청년 혜택(D1~D2), 전체 평가와 의견(E1~E5)
- 설정: 이메일 주소 수집 안 함, 응답 수정 허용 안 함
- 문항 제목이 `B1.`처럼 코드와 마침표로 시작해야 집계 스크립트가 읽습니다. 폼에서 문구를 고칠 때도 코드는 남겨 두세요.
- B, C, E2는 선형 배율이라 응답이 숫자로 내려받아집니다. C 문항은 써 보지 않은 기능이면 비워 둘 수 있습니다.

## 7. 응답 집계

1. 구글 폼 응답 탭에서 CSV로 내려받아 `private/설문응답.csv`로 저장합니다. `private/`는 커밋되지 않습니다.
2. 관찰 기록이 있으면 `private/사용자테스트_관리.csv`를 최신으로 맞춥니다.
3. 집계 스크립트를 실행합니다.

```bash
python scripts/user_test_summary.py private/설문응답.csv --observations private/사용자테스트_관리.csv
```

출력되는 내용:

- README "사용자 테스트 결과" 표에 그대로 붙일 수 있는 표
- 결과보고서(05)의 참여자 표와 핵심 지표 값
- 결과보고서용 기능별 평가, 기능별 사용·도움 응답 수
- 자유 의견 목록 (응답 순서 번호). 피드백 Top 5를 고를 때 씁니다.

SUS는 10문항 중 하나라도 비면 그 사람을 SUS 평균에서 빼고, 몇 명 기준인지 함께 표시합니다.

## 8. 피드백 반영

1. 자유 의견과 관찰 메모에서 **2명 이상이 같은 지점을 지적한 것**을 고릅니다.
2. 그중 오늘 고칠 수 있는 것(문구, 버튼 위치, 설명 추가) 1~2개를 `user-feedback` 라벨 이슈로 등록합니다. 이슈에는 익명 인용, 같은 의견을 낸 응답 수, 해당 화면, 조치 계획을 적습니다.
3. 수정 PR 본문에 `Closes #이슈번호`와 수정 전후 화면 캡처를 넣습니다.
4. 결과보고서 4절 표에 "피드백 → 조치 → 전후 → 이슈/PR"로 정리합니다.

이번 일정으로는 개선 후 재테스트(2차)를 하기 어렵습니다. 결과보고서의 "2차 결과" 열은 "측정 안 함"으로 두고, 다음 단계에 적습니다.

## 9. 기록 원칙

- 숫자는 실제로 받은 응답과 관찰 기록에서만 가져옵니다. 응답이 적어도 그대로 씁니다.
- 계획(10명, 1주일)보다 줄어든 인원과 기간, 측정하지 않은 지표(재방문)는 결과보고서에 명시합니다.
- 팀원 본인과 팀원 리뷰에서 나온 의견은 실사용자 피드백과 구분합니다.
- 인용에서 이름이나 소속을 알 수 있는 표현은 지웁니다.
