# n8n 연결 준비

`policy_refresh.json`, `weekly_checkin.json`을 Import from File로 불러옵니다. 기본은 비활성입니다. 실제 발송이나 스케줄을 실행하지 않았습니다.

- 시간대: Asia/Seoul
- 정책 갱신: 매일 03:00
- 주간 체크인: 일요일 20:00
- 변수 `SADARI_BASE_URL`: 팀 배포 주소. 끝에 / 없이 입력합니다.
- 모든 내부 HTTP 노드의 Header Auth 자격 증명: 이름 X-Internal-Key, 값은 서버의 INTERNAL_API_KEY. JSON 파일에 키를 쓰지 않습니다.
- 정책 알림 HTTP 노드의 URL: 팀 디스코드 웹훅을 n8n 비밀 저장 방식에 맞춰 설정합니다. 내보낸 JSON의 $vars.DISCORD_WEBHOOK_URL 표현식은 연결 위치 표시이며, 실제 웹훅 주소를 공개 변수·저장소에 기록하지 않습니다.
- 이메일 노드: 팀 Gmail OAuth2 자격 증명을 선택합니다. 발송은 실제 사용자 동의가 있는 경우에만 진행합니다.
- 실행 성공·실패 데이터 저장을 none으로 설정했습니다. n8n 인스턴스의 전역 로그·실행 데이터 보관 정책도 운영자가 확인합니다.

정책 자동화는 변화가 있는 경우 신규/변경 건수만 디스코드로 알립니다. 갱신 실패는 노드가 실패하도록 두고 기존 캐시는 유지합니다. n8n 운영자는 실행 실패 알림 또는 오류 워크플로우를 설정해야 합니다.

주간 자동화는 준비 → 대기 건 분리 → 발송 선점 → 허가된 결과만 통과 → Gmail → 완료 기록 순서입니다. 선점된 건은 재실행해도 다시 발송 대상이 되지 않습니다. 선점 이후 실패한 건은 자동 재발송하지 않으며 담당자가 발송 이력을 보고 처리합니다. 실행 도중 회원 탈퇴/동의 철회가 발생하는 경우를 포함한 운영 점검이 필요합니다.

호스팅은 팀 공용 n8n 인스턴스 사용을 우선 제안합니다. 현재 계정·인스턴스가 제공되지 않아 호스팅 결정을 확정하거나 생성하지 않았습니다. 로컬 PC 시험은 PC가 꺼지면 예약이 실행되지 않습니다. n8n에서 JSON을 불러온 뒤 노드 버전, 인증, 변수 접근 권한을 확인하고 가짜 계정으로 먼저 검증해야 합니다.
